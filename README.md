# الو تكسي Manager

أنشئ نظام ويب متكامل ومتجاوب لإدارة طلبات وعمولات مكتب «الو تكسي»، باللغة العربية وباتجاه RTL، مع تصميم Mobile First احترافي، واضح وخفيف، دون تغيير الفكرة الأساسية للنظام الحالي.



النظام ليس تطبيق توصيل أو خرائط. هو نظام داخلي لتسجيل الطلبات وربطها بالكباتن وحساب العمولات الشهرية وإدارة الموظفين.



استخدم Supabase لقاعدة البيانات والمصادقة وتطبيق Row Level Security، بحيث تُطبق الصلاحيات فعلياً من قاعدة البيانات، وليس فقط بإخفاء عناصر الواجهة.



## الهوية والتصميم



- واجهة عربية RTL بالكامل.

- تصميم احترافي بسيط وغير ضخم.

- اللون الأساسي أصفر مستوحى من سيارات التكسي.

- اللون الثانوي كحلي داكن أو أسود.

- خلفيات بيضاء ورمادية فاتحة.

- الأخضر للحالات الناجحة والنشطة.

- الأحمر للحذف والتحذير فقط.

- الخط المقترح: Tajawal أو IBM Plex Sans Arabic.

- الواجهات تعمل بشكل ممتاز على الهاتف والكمبيوتر.

- على الهاتف استخدم بطاقات بدلاً من الجداول العريضة.

- على الكمبيوتر استخدم جداول مرتبة ورؤوس ثابتة.

- القائمة الجانبية تنزلق من اليمين على الهاتف.

- لا تعرض معلومات كثيرة أو بطاقات إحصائية غير ضرورية.

# صلاحيات المستخدم



المستخدم يستطيع فقط:



- إضافة طلب جديد.

- مشاهدة الطلبات التي أدخلها بنفسه ضمن الدورة الحالية فقط.

- تعديل الطلب الذي أدخله بنفسه.

- حذف الطلب الذي أدخله بنفسه.

- البحث ضمن طلباته.

- مشاهدة عدد الطلبات التي أدخلها فقط.



المستخدم لا يستطيع:



- مشاهدة طلبات المستخدمين الآخرين.

- مشاهدة عمولة أي طلب.

- مشاهدة إجمالي العمولات.

- مشاهدة مجموع قيم الطلبات التي أدخلها.

- مشاهدة إحصائيات مالية.

- الدخول إلى صفحة الكباتن أو المستخدمين أو التقارير.

- تعديل أو حذف طلب أدخله مستخدم آخر.

- مشاهدة الأرشيفات الشهرية.

- مشاهدة نسبة عمولة الكابتن.



مهم جداً:



في لوحة المستخدم لا تعرض مجموع قيمة الطلبات ولا مجموع العمولات.



اعرض فقط:



- اسم المستخدم.

- عدد الطلبات التي أدخلها خلال الدورة الحالية.

- زر إضافة طلب جديد.

- قائمة طلباته الحالية.



داخل قائمة طلبات المستخدم لا تعرض قيمة الطلب ولا العمولة بشكل مباشر.



اعرض فقط:



- رقم الطلب.

- اسم الكابتن.

- التاريخ.

- وقت الإدخال.

- حالة الطلب.

- أزرار العرض والتعديل والحذف.



قيمة الطلب تظهر للمستخدم فقط داخل نموذج إضافة الطلب أو تعديل الطلب، لأنه يحتاج إلى إدخالها أو تصحيحها.



# شاشة إضافة طلب للمستخدم



صمم شاشة إضافة طلب سريعة جداً ومناسبة للعمل المتكرر.



الحقول المطلوبة:



1. التاريخ.

2. قيمة الطلب.

3. اسم الكابتن.



يمكن إضافة ملاحظة اختيارية فقط إذا لزم الأمر.



## حقل التاريخ



- لا تجعل المستخدم يكتب التاريخ يدوياً.

- استخدم Date Picker أو قائمة اختيار تاريخ.

- يكون تاريخ اليوم محدداً افتراضياً.

- يستطيع المستخدم اختيار تاريخ آخر من التقويم.

- اعرض التاريخ بصيغة عربية واضحة.

- احفظ الوقت الفعلي لإضافة الطلب تلقائياً في قاعدة البيانات.

- التاريخ المختار يمثل تاريخ الطلب، ووقت الإنشاء يسجل تلقائياً.

قواعد الحقل:

- يمنع الأحرف والرموز غير الرقمية.

- يعرض فواصل الآلاف تلقائياً.

- يمنع القيمة صفر أو القيمة السالبة.

## اختيار الكابتن



- يظهر الكباتن ضمن قائمة Dropdown.

- داخل القائمة يوجد مربع بحث واضح.

- يستطيع المستخدم البحث باسم الكابتن.

- يمكن البحث أيضاً برقم الهاتف أو رقم المركبة إذا كانت البيانات موجودة.

- اعرض الكباتن النشطين فقط.

- أظهر آخر الكباتن الذين اختارهم المستخدم في أعلى القائمة لتسريع الإدخال.

- لا تعرض نسبة عمولة الكابتن للمستخدم.

- لا تعرض إجمالي طلبات أو عمولات الكابتن.



## أزرار النموذج



- حفظ الطلب.

- حفظ وإضافة طلب آخر.

- إلغاء.



بعد الحفظ:



- امنع تكرار الحفظ بسبب الضغط المزدوج.

- اعرض رسالة نجاح واضحة.

- اعرض رقم الطلب.

- نظف الحقول عند اختيار «حفظ وإضافة طلب آخر».

- سجل المستخدم الذي أضاف الطلب ووقت الإضافة تلقائياً.



# تعديل وحذف طلب المستخدم



المستخدم يستطيع تعديل أو حذف طلب أدخله بنفسه فقط.



عند التعديل:



- يظهر نموذج يحتوي على التاريخ وقيمة الطلب والكابتن.

- تسجل القيمة القديمة والجديدة.

- يسجل وقت التعديل.

- يسجل اسم المستخدم الذي نفذ التعديل.



عند الحذف:



- لا تحذف الطلب نهائياً من قاعدة البيانات.

- استخدم Soft Delete.

- اعرض نافذة تأكيد.

- اجعل المستخدم يختار سبب الحذف:

  - إدخال خاطئ.

  - طلب مكرر.

  - اختيار كابتن خاطئ.

  - قيمة خاطئة.

  - سبب آخر.

- احفظ سبب الحذف واسم المستخدم ووقت الحذف.

- يستطيع المدير مشاهدة الطلبات المحذوفة واستعادتها.



بعد أرشفة الدورة الشهرية، يمنع المستخدم من تعديل أو حذف طلبات الدورة المؤرشفة.

# نظام الدورات الشهرية وأرشفة العمولات



هذا الجزء أساسي جداً.



لا تعتمد على حذف الطلبات عند نهاية الشهر.



أنشئ نظام Accounting Periods أو Commission Cycles.



كل طلب يجب أن يرتبط بدورة عمولات محددة عبر period_id.



يوجد دائماً دورة واحدة فقط حالتها:



Open



وتكون هي الدورة الحالية التي تسجل داخلها الطلبات الجديدة.



يمكن أن تحمل الدورة اسماً مثل:



- عمولات يوليو 2026.

- عمولات أغسطس 2026.

- دورة من 1 أغسطس إلى 31 أغسطس.



المدير يستطيع إنشاء الدورة الحالية وتحديد:



- اسم الدورة.

- تاريخ البداية.

- تاريخ النهاية الاختياري.

- ملاحظة اختيارية.



## زر إغلاق وأرشفة الدورة



أضف في لوحة المدير زر واضح:



«إغلاق وأرشفة الدورة الحالية»



عند الضغط عليه:



1. اعرض ملخص الدورة:

   - عدد الطلبات.

   - إجمالي قيمة الطلبات.

   - إجمالي العمولات.

   - عدد الكباتن الذين لديهم طلبات.

   - تاريخ بداية الدورة.

   - تاريخ الإغلاق.



2. اعرض رسالة تحذير:

   - بعد الإغلاق لن يمكن للمستخدمين تعديل أو حذف طلبات هذه الدورة.

   - ستنتقل كل الطلبات إلى الأرشيف.

   - ستبدأ دورة جديدة بأرقام صفرية.



3. اطلب من المدير كتابة ملاحظة أو رقم إيصال قبض العمولة بشكل اختياري.



4. بعد التأكيد:

   - غيّر حالة الدورة من Open إلى Archived.

   - اقفل جميع طلباتها أمام التعديل.

   - احتفظ بجميع البيانات داخل قاعدة البيانات.

   - احتفظ بإجمالي الطلبات والعمولات لكل كابتن داخل الأرشيف.

   - احتفظ بعدد الطلبات التي أدخلها كل مستخدم داخل الأرشيف.

   - أنشئ دورة جديدة فارغة حالتها Open.

   - اجعل جميع إحصائيات الدورة الجديدة تساوي صفراً.

   - يصبح عدد الطلبات الحالية صفراً.

   - تصبح عمولات الكباتن في الدورة الجديدة صفراً.

   - يصبح عدد طلبات كل كابتن في الدورة الجديدة صفراً.

   - يصبح عدد طلبات كل مستخدم في الدورة الجديدة صفراً.

   - تبقى أسماء الكباتن موجودة.

   - تبقى حسابات المستخدمين موجودة.

   - تبقى نسب عمولات الكباتن محفوظة.

   - لا تحذف أي كابتن أو مستخدم.



مهم:



لا تقم فعلياً بتصفير أو حذف السجلات القديمة.



يجب أن تعتمد الإحصائيات الحالية على period_id الخاص بالدورة المفتوحة فقط.



الأرقام القديمة تبقى مرتبطة بالدورة المؤرشفة، لكنها لا تظهر ضمن إحصائيات الدورة الجديدة.



# صفحة الأرشيف



أنشئ صفحة للمدير باسم:



«أرشيف الدورات»



تعرض قائمة بكل الدورات المؤرشفة.



لكل دورة اعرض:



- اسم الدورة.

- تاريخ البداية.

- تاريخ الإغلاق.

- عدد الطلبات.

- إجمالي قيمة الطلبات.

- إجمالي العمولات.

- المستخدم الذي أغلق الدورة.

- ملاحظة الإغلاق.



عند فتح دورة مؤرشفة اعرض:



- جميع طلباتها.

- تفاصيل الكباتن.

- عدد طلبات كل كابتن.

- عمولة كل كابتن.

- عدد الطلبات التي أدخلها كل مستخدم.

- الطلبات المعدلة.

- الطلبات المحذوفة.

- تقرير مالي كامل.



الدورة المؤرشفة تكون Read Only.



لا يسمح بالتعديل أو الحذف داخلها.



أضف خيارات:



- تصدير PDF.

- تصدير Excel.

- طباعة التقرير.



يمكن للمدير البحث في الأرشيف حسب:



- اسم الدورة.

- الشهر.

- السنة.

- الكابتن.

- المستخدم.

- رقم الطلب.



# العمولات داخل الدورة الحالية



لكل كابتن احسب:



- عدد الطلبات الحالية.

- مجموع قيمة الطلبات الحالية.

- نسبة العمولة.

- قيمة العمولة المستحقة.



معادلة العمولة:



commission_amount = order_amount × captain_commission_percentage ÷ 100



نسبة العمولة تحفظ داخل سجل الطلب عند إنشائه، حتى لا تتغير عمولة الطلبات القديمة إذا قام المدير بتغيير نسبة الكابتن لاحقاً.



مثال:



إذا كانت قيمة الطلب 15,000 ل.س ونسبة الكابتن 7%:



العمولة = 1,050 ل.س



هذه المعلومات تظهر للمدير فقط.

- يستطيع تعديل طلباته الموجودة داخل الدورة المفتوحة فقط.

- يستطيع حذف طلباته الموجودة داخل الدورة المفتوحة فقط.

- لا يستطيع قراءة commission_amount.

- لا يستطيع قراءة commission_percentage_snapshot.

- لا يستطيع قراءة إجماليات مالية.

- لا يستطيع الوصول إلى الأرشيف.

- لا يستطيع إدارة الكباتن أو المستخدمين.



المدير:



- يستطيع قراءة وإدارة جميع البيانات.

- يستطيع إغلاق الدورات.

- يستطيع مشاهدة الأرشيف.

- يستطيع استعادة الطلبات المحذوفة.



لا تعتمد على إخفاء الحقول من الواجهة فقط. طبق الحماية في قاعدة البيانات وواجهات API أيضاً.
